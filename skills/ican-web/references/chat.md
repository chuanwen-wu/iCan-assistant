# 个人与群聊读取

入口：https://icanplatform.feishu.cn/next/messenger/

## 会话列表

1. 等待“消息”界面出现。列表会混有个人聊天、群聊、部门群、外部会话和机器人；只按页面明确显示的信息分类，不能仅凭名称或“外部”标记判断是群。
2. 默认请求或空的 `/chat`：列出最近最多 10 个会话的名称、可确认类型、最近消息时间、预览和未读标记。预览只用来概览，不作为完整消息记录。
3. 用户要“所有个人／群聊天”时，滚动会话列表并去重直到明确到底。固定／置顶区与普通列表可能重复；不要把机器人误列为个人联系人。无法穷尽或类型无法判断时说明“已加载会话”和未确认部分。

## 打开指定个人／群会话

1. 优先选择列表中直接匹配的联系人／群名。不在当前列表时用页面提供的搜索或会话查找功能；全局搜索可能同时返回联系人、群、消息、文档，先核对结果类别。
2. 同名联系人或群要核对成员、部门、外部标记等当前可见信息；仍不能唯一确定时请用户澄清。
3. 精确点击会话名，重新观察并核对消息面板的标题与目标一致后读取。会话列表摘要不代表已打开对话；不要把搜索结果预览充作消息详情。
4. 不输入或聚焦消息编辑器，不按可能发送消息的快捷键，不点击语音／通话、加群、表情回复或发送控件。

## 消息与历史范围

- 按消息读取发送人、时间、正文和消息类型。群聊区分每条消息的发送人；连续消息可能省略重复姓名／日期，只能在同一明确分组内沿用。
- 读取“最近 N 条”时，确认是否已在会话最新位置；若打开在搜索命中或历史位置，使用页面可见的回到底部／最新消息入口。取得足够消息后按时间顺序呈现。
- 读取“今天／本周／某日期范围”时，在**消息历史区域**向上滚动加载，直到跨过起始日期，再筛选区间；搜索支持日期条件时优先用页面支持的筛选。会话列表和消息历史分别滚动，不能相互替代。
- 对相邻加载批次保留重叠位置／上下文并去重。同一人同一分钟发两条相同内容也可能是真实的两条消息；优先用页面实际提供的稳定消息引用，缺少引用时不要仅凭文本相同全局去重。
- 引用、回复串、话题与转发卡片应与当前消息区分，按用户问题需要展开；同一被引用消息不能重复算作新消息。图片／文件／语音／视频只报告页面显示的类型与文字；需要具体内容再预览、下载或使用相应读取能力。
- 到达明确历史起点、用户指定数量／日期边界后结束。若权限、网页保留范围或加载失败阻止继续，报告已经读取的会话、日期和条数，不声称取得完整历史。

总结时把结论／待办关联到会话、发送人和消息时间；只使用页面真实可见的消息链接。创建任务或对外通知是后续动作，交给 `office-router` 对应技能并在执行前确认。
